# RBP screening and genome classification

Use native genomic inputs for model prediction, or existing tables for screening
and domain summaries. Use a new output directory for each run.

## Sequence prediction

Install the models into your data directory:

```bash
phanet setup-models --models rbp taxonomy --out "$PHANET_DATA/models"
```

See [model installation](models.md) for manual downloads and offline use.
You can also use bundles produced by [training](training.md#rbp-and-taxonomy-models).
From nucleotide FASTA:

```bash
phanet predict-rbp --input query-genomes.fna \
  --config "$PHANET_DATA/traditional.json" --esm-model "$PHANET_ESM_MODEL" \
  --model "$PHANET_DATA/models/rbp" --device cuda --out rbp-results
phanet predict-taxonomy --input query-genomes.fna \
  --config "$PHANET_DATA/traditional.json" --esm-model "$PHANET_ESM_MODEL" \
  --model "$PHANET_DATA/models/taxonomy" --method glm --device cuda --out taxonomy-results
```

Replace `--input` and `--config` with `--dataset prepared/dataset` to reuse native
records, or `--genbank genome.gb` for annotated GenBank files. Replace
`--esm-model` with `--embeddings protein-embeddings` to reuse complete ESM2 vectors.
Use `--device cpu` for CPU execution and `--batch-size` to adjust memory use.

For combined taxonomy, use `taxonomy-combined-fit/model`, `--method combined`,
`--network-config "$PHANET_NETWORK_CONFIG"` and
`--reference-labels taxonomy-combined-fit/reference-labels.tsv`.
`predictions.tsv` and `predictions.json` report the accepted lineage per genome.

Standalone RBP models score every protein directly and leave `infection_score`
empty. Models trained with Infection scores require `--annotation-model` and
`--network-config` for two-stage screening.

RBP writes `rbp.tsv` with classifier scores, pipeline scores and candidate
decisions for every protein. To reuse Infection scores generated by
`score-infection`, supply `--infection-scores infection-input/infection.tsv`
in place of `--annotation-model` and `--network-config`. Protein IDs and full
sequence hashes must match. `summary.json` contains counts.

## RBP screening

```bash
phanet rbp screen --scores rbp-scores.tsv \
  --evidence-version my-scores-v1 --out rbp-results
```

The score TSV requires `protein_id`. Optional columns are `classifier_score`,
`tmvec_score`, `infection_score` and GO term IDs. Scores are in [0, 1], except
TM-Vec cosine scores in [-1, 1]. Blank cells or NaN represent missing scores.
A `predict-go` table such as `go/go_BP.tsv` can be used as `--scores`.

| Option | Input |
|---|---|
| `--monomer` | TSV: `protein_id`, `mean_plddt` (0–100) |
| `--complex` | TSV: `protein_id`, `iptm` (0–1), `buried_surface_area` (square angstroms), `tm_score` (0–1) |
| `--literature` | One protein ID per line |
| `--config` | JSON with screening thresholds |

To use `infection_score`, supply a config containing `infection_threshold`.
Other configurable keys are `go_threshold`, `tmvec_threshold`,
`classifier_threshold`, `plddt_threshold`, `iptm_threshold`,
`buried_surface_area` and `tm_score_threshold`.

To compute TM-Vec scores from existing vectors, supply
`--tmvec-query-vectors query.npz --tmvec-reference-vectors reference.npz
--tmvec-reference-version my-reference-v1`. Each NPZ contains string `ids`
and numeric `features` arrays. Query IDs must exactly match the score table;
query and reference vectors must use the same encoder, checkpoint and dimension.
Use finite, nonzero vectors. Choose either vector inputs or a `tmvec_score`
column. `--tmvec-top-k` controls the number of retrieved matches.

Outputs: `candidates.tsv` contains scores and screening results; `report.json`
contains stage counts and literature matches. Vector input also produces
`tmvec_retrieval.tsv`.

## Reuse GO output

After the [downstream workflow](downstream.md), screen its BP scores directly:

```bash
phanet rbp screen --scores lambda-analysis/go/go_BP.tsv \
  --evidence-version my-go-model-v1 --out lambda-analysis/rbp
head -n 6 lambda-analysis/rbp/candidates.tsv
```

Use the version of the model that produced the GO table for `--evidence-version`.
The GO-only command reports preliminary screening; to include the classifier
stage, add a `classifier_score` column aligned by `protein_id` to a copy of the
score table. Structural tables are supplied with `--monomer` and `--complex`.

## Domain summaries

```bash
phanet rbp domains --domains domains.tsv \
  --evidence-version my-domains-v1 --out domain-summary
```

The TSV requires `protein_id`, `domain` (or `domain_id`), `start`, `end` and
`protein_length`. Coordinates are **0-based, half-open**. Alternatively, provide
lengths with `--protein-lengths lengths.tsv` (`protein_id`, `length`).

Outputs: `domains.tsv` contains the intervals; `report.json` contains domain
counts and positions.

## Genome classification

```bash
phanet taxonomy --queries query-genomes.txt --hits taxonomy-hits.tsv \
  --reference-version my-reference-v1 --out taxonomy-results
```

`--queries` contains one genome ID per line, including genomes without hits.
The hit TSV requires `genome_id`, `query_protein_id`, `weight` (0–1) and available
rank columns: `order`, `family`, `subfamily`, `genus`.
`reference_id` is optional. Leave missing ranks blank and use globally unique
protein IDs.

Use `--config thresholds.json` to set `min_support`, `min_proportion`,
`min_confidence`, `min_margin` or `rank_overrides` (per-rank settings).

To classify with genome features, add:

```bash
phanet taxonomy --queries query-genomes.txt \
  --features query.npz --train-features train.npz --labels labels.tsv \
  --feature-version my-encoder-v1 --reference-version my-reference-v1 \
  --out taxonomy-features
```

Each NPZ contains string `ids` and a finite genome-by-dimension `features`
matrix. Use the same encoder, pooling and dimensions for both files. Query
features must cover exactly the query list; training and query IDs must be
disjoint. The label TSV contains `genome_id`, `partition` and rank columns.
Rows with `partition=train` must exactly match the training feature IDs.
Add `--hits` to combine features with reference hits.

Outputs: `predictions.tsv` and `predictions.json` contain assignments for each
genome and rank. Feature runs also write `fitted-heads.json`.

See the [Python API](api.md) for equivalent in-memory calls. Run each command
with `--help` for all options.
